How Whisper turns speech into text

Learned, not programmed

Whisper was trained on about 5 million hours of speech. It writes the most likely words, so rare names like “Waku Ghin” lose to common words unless we hint them.

Built for whole clips

It reads audio in 30-second windows and has no built-in streaming. That is why Whisper Live has to re-run it every second.

Our vocabulary, twice

Before: the term list goes in as a prompt (a soft hint). After: vocab.py fixes known mishearings and near-misses.

Two ways to run the same model · 2 / 5

Whisper waits for Stop. Whisper Live writes while you talk.

Whisper · record, then transcribe

Strengths

  • Most accurate: sees the whole clip and searches for the best wording.
  • Simple request and response; easy to retry and scale.
  • Lowest GPU use per minute of speech: one pass.

Limits

  • Nothing appears until Stop; the wait grows with length.
  • About 4 minutes per recording in the POC (Vertex 1.5 MB request cap).

Whisper Live · streaming

Strengths

  • Text appears about 1–1.5 s behind the speaker.
  • Same model and same vocabulary clean-up as Whisper.
  • No length limit; ends with a final pass after Stop.

Limits

  • Re-runs the model about once a second: roughly 3–5× more GPU per minute.
  • The last few words can change; words at the edges are a little less accurate.
  • Needs an open connection (WebSocket), so one GPU serves fewer people.

The POC as built · 4 / 5

One app, three engines, one Whisper image

Built our own Whisper container

Google's ready-made Whisper takes no vocabulary prompt, so we serve faster-whisper ourselves with the prompt and vocab.py.

Vertex can't stream

Vertex endpoints take one request at a time (max 1.5 MB) and can't hold a WebSocket. Live therefore runs on Cloud Run.

GPU supply varies by region

The Singapore deploy waited 30+ minutes for an L4 and never got one. Plan region fallbacks on Azure too.

Recommendation · 5 / 5

Measure on our own phrases, then build on Azure

Recommendation

Start the Azure build with Azure OpenAI transcribe plus our vocab.py clean-up: the lowest cost and nothing to run.

Keep self-hosted Whisper as plan B. It is already built in this POC and moves to Container Apps if Azure OpenAI misses our terms or data must stay in our own subscription.

Add live text only if staff actually need to read along while speaking.

Decision criteria

  • Hit rate on our venue, drink and programme names
  • Data handling: guest preferences are personal data
  • Live text needed, or Stop-then-text enough?
  • Volume: self-hosting pays off only at steady high use

Open questions

  • Azure OpenAI transcription in Southeast Asia regions
  • Where the vocabulary list lives and who edits it
  • Mixed English and Chinese speech
